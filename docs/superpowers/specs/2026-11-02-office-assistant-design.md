# 桌面办公助手：待办、会议纪要与日语商务实时翻译

日期：2026-11-02。状态：用户已通过“ok”确认书面设计；进入阶段 A 实施计划，尚未进入实现。

## 目标与已确认需求

为当前 Mac 创建个人桌面办公助手，完成日常待办记录、完成情况标记、日常提醒、语音识别、会议纪要、自动识别待办及日语商务实时翻译。用户已选择桌面使用，同时需要面对面沟通和电脑线上会议两种收音场景。

成功标准：一次会议从收音、中日字幕、纪要生成、提取行动项到加入待办和提醒，可以在同一应用中完成；日常待办不依赖会议入口。

## 推荐方案与设计假设

推荐 Mac 原生应用。与跨平台桌面壳、浏览器安装应用相比，原生方案更贴合本机的音频采集、菜单栏与通知体验；首版只交付 Mac 版本。

随设计确认的默认值：中文界面；每天 09:00 汇总；用户当前时区默认 Asia/Shanghai；实时翻译以字幕输出，包含日语到中文和中文到商务日语；文字及录音可供云端 AI 处理，历史记录保存在本机。不是完全离线产品。AI 接口需要联网、可用账号及相应调用费用，接入前单独完成凭证配置。

## 页面与使用流程

主窗口侧栏包括：今日待办、全部待办、已完成、会议记录、设置。关闭窗口后保留菜单栏入口；真正退出后停止采集和在线处理。系统已经接受的通知由系统调度，最终展示仍受通知设置、睡眠和关机状态影响。

### 1. 日常待办

- 手动创建、编辑、删除、搜索，状态为待处理、进行中、已完成，可撤销完成。
- 支持文字快速输入及短语音记录，解析结果展示标题、负责人、截止时间和提醒规则，保存前可以修改。
- 个人身份名称在设置中维护；负责人未知显示未指定，不能将未指明的任务自动归到自己。
- 支持一次性、每天、工作日、每周重复；完成一个重复任务只完成本次实例，按规则生成下一实例。
- 日汇总默认为 09:00，可以修改或关闭。到点通知可完成或稍后 10 分钟提醒；完成、删除或更改截止时间时取消旧通知。
- 逾期任务留在今日视图；启动、恢复运行时补充显示遗漏提醒，不集中弹出所有历史通知。
- 时间不明的任务可保存且标记待补充，不凭空生成精确提醒。仅日期任务保存前明确显示采用的默认提醒时间。
- 重复规则保留所属时区，明确时间保存为绝对时间；相对日期以记录发生时间及所属时区解析，不能按后续重试时的日期重新计算。

### 2. 面对面与线上会议

- 开始会议时选择面对面或线上会议，填写标题、参会者、语言模式及术语。
- 面对面使用选定麦克风。线上会议采集用户选定来源的系统音频，可同时开启本地麦克风；分开记录音源并显示音量状态。耳机为推荐使用方式，降低麦克风再次录入外放声音的可能。
- 在线会议不创建入会机器人，不自动发送消息，不宣称适配所有会议软件。先在实际目标软件上验证系统音频采集。
- 显示录音计时、暂停、继续、停止和音源状态；暂停或停止后立即停止相应音频上传。
- 提供音频文件导入，通过系统解码能力检查格式，无法处理时明确提示。长音频分块并保留关联顺序，失败可重试。
- 需要麦克风及系统录音权限时，在对应功能入口申请；拒绝后仍能管理待办、粘贴文字、查看历史。

### 3. 日语商务实时翻译

- 会议进行中逐步显示原文字幕与译文，不等待整场录音完成。原文区分临时片段与已定稿片段；译文显示处理中、已完成或需重试。
- 默认日语转中文；可切换中文转商务日语。中日混合模式作为显式可选设置，按测试效果决定是否提示使用单一方向。
- 中文转日文采用商务敬语，保持数字、金额、日期和承诺原意；提供术语表，包括专有名词及期望译法，不保证模型每次都遵循。
- 使用有界上下文维护相邻片段一致性，避免每个片段携带整场转写；译文按片段编号回填，防止并行请求完成顺序改变字幕顺序。
- 不承诺零延迟。第一版测试目标为正常网络下，明确句段结束后译文出现的 P95 不超过 5 秒；未达到时报告实测值，不把目标当成已验证能力。
- 首版不包含自动语音播报、会议软件虚拟麦克风或自动代替用户发言。

### 4. 纪要与自动提取待办

- 停止录音后等待现有转写收尾，再基于已保存的最终原文生成纪要。中文纪要为默认，可导出中日双语 Markdown 或纯文本。
- 纪要包含议题摘要、明确决定、未解决问题及行动项，允许人工修改；每个行动项关联原文片段。
- 已确认原文片段可在会议中定期触发行动项候选提取，会后进行整合去重。候选不是正式任务，不在临时字幕阶段自动创建任务。
- 结构化候选包含标题、负责人、原始时间表达、解析后的截止时间、来源会议及片段标识、需澄清字段。
- 用明确的承诺或分工作为行动项依据；问题、假设、否定和已经完成的事项不能直接当作新任务。
- 缺失负责人、模糊时间或不明确承诺标记待确认，不补造事实。“明天下午”保留日期和时段，要求确认具体提醒时间。
- 候选集中审阅，可以编辑、忽略或批量加入。重复提取、重试、再次点击加入均不得产生重复任务；已加入后再次生成纪要不得覆盖用户改过的任务。
- 音源标签不是人员身份；系统音频中多人的发言默认不具名，可手动标注。没有依据时不猜测发言者及任务负责人。

## 技术结构

以 SwiftUI 构建 Mac 原生界面，Core Data 本地持久化，UserNotifications 调度通知。初始部署目标为 macOS 14 及以上，当前开发机为 macOS 26.6.2；最低版本支持需要实际编译与相应环境验证，不能仅凭当前机器宣称已验证。

应用划分为：待办与重复规则、提醒调度、会议音频采集、转写连接、翻译、纪要与行动项提取、本地存储、设置与凭证。各模块通过结构化数据通信，音频与网络工作不阻塞界面。

- 麦克风通过 AVAudioEngine 采集，系统音频通过 ScreenCaptureKit 采集；独立适配各自的格式和生命周期。
- 云端语音适配层支持 OpenAI、微软 Azure Speech、阿里云通义听悟的实时转写与硅基流文件/短片段转写；文字翻译支持 OpenAI、DeepSeek、硅基流，识别与翻译分别选择。DeepSeek 当前官方模型接口不列音频输入，不提供其语音识别选项。按实际账号验证模型权限与中日语效果后启用。
- 语音统一重采样为接口要求的 PCM 单声道格式，按输入音源分别维护流。按照官方接口要求实现客户端语音结束检测及提交，不能假设所有模型支持服务端语音检测。
- 原文定稿后触发文字翻译；纪要和行动项走结构化文字生成接口。文字模型为配置项，在接入阶段按照账号可用性及测试表现确定，不在本设计中假定某个未验证模型可用。
- 转写事件通过服务端 item ID、音源 ID 和本地序号合并、排序、去重。时间标记来自本地采集时间，只表示片段范围，不冒充模型词级时间戳。
- 不展示不存在的置信度分数；模型不返回说话人或词级时间时，使用上述应用级标注。
- 本地数据库保存任务、重复规则、会议、片段、纪要、候选、术语及设置。凭证放系统钥匙串，不进入数据库、日志或导出文件。
- 用户选择是否保留原始音频；默认仅保留转写和结果，音频以临时分块缓冲供短时恢复，完成处理后清理。删除会议可一并删除本地音频和衍生记录；已加入的独立任务保留并提示来源已删除。

## 失败恢复与后台行为

保存已定稿转写后再启动衍生处理。会议、字幕片段和 AI 作业具有独立状态；网络错误不清空已保存内容。重启后显示中断会议，不自动开始录音。

断网时保留已完成内容，使用最多 60 秒的有界本地音频缓冲；达到上限自动暂停采集并明确提示。重连后先标识缺口，再由用户继续或选择处理缓冲，不无限排队。重试保留原片段 ID，避免重复生成译文或任务。权限、认证和额度错误需要对应修正，不能无限自动重试。

提醒调度维护有限的近期待处理请求，数据库是任务状态来源；在任务变更、启动、唤醒及通知动作后重新校准。关机期间不承诺即时通知；应用恢复后展示遗漏项。首版可由用户选择登录时启动。

## 交付拆分与验收

这是一个包含语音和桌面生命周期的新系统，实施应按依赖分为三个可独立验收的阶段；本文件覆盖整体产品范围，先为阶段 A 编写详细实施计划，避免用一份计划直接铺开全部系统。

1. 阶段 A：可启动桌面应用、待办、本地保存、重复规则、每日与到期提醒、菜单栏。验证重启不丢数据，完成会取消旧提醒，重复实例不重叠，日期与时区逻辑正确，通知权限拒绝时仍可使用。
2. 阶段 B：AI 接入、麦克风和系统音频、文件导入、实时中日字幕和商务日语翻译。对真实麦克风与至少一种目标会议软件验证双方收音、暂停停止、片段排序、断网缓冲及可见错误；以代表性的中日商务音频统计字幕与译文延迟，并检查金额、日期及术语。
3. 阶段 C：会议纪要、自动候选、确认加入待办和导出。使用含有明确指派、否定、模糊时间、跨日、重复表述的文本样例验证提取；必须能追溯原文、缺失字段不伪造、反复加入不重复。

每个阶段区分本地自动验证、真实系统权限验证和真实 AI 联调。没有凭证时只能标记云端功能待联调，不能把模拟结果当作真实识别或翻译。

交付包括源代码、可本地启动的 .app、操作说明及验证记录。首版针对本机使用，不包含 App Store 发布、多人协作、账号同步或对外自动发送。

## 官方资料与已知接入依据

- [OpenAI 实时转写](https://developers.openai.com/api/docs/guides/realtime-transcription)：流式增量、片段完成事件、格式和客户端语音提交要求；当前推荐模型不返回词级时间、说话人标签或置信度分数。
- [OpenAI 转写工作流](https://developers.openai.com/api/docs/guides/transcription)：区分已录音文件与实时音频，选择对应接口。
- [Apple ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit)：作为系统音频采集框架；实现前继续核对具体 API 的版本及权限要求，并在本机实际验证。
